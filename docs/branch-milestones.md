## ① LLM Wiki 编译链路（09-18）

**解决什么**：RAG 优化「能不能捞到」，但记忆是碎片、没有结构。这一步让零散记忆
变成**可读的知识库**——两级编译：会话内归纳成页 → 跨会话按主题聚合成实体页；
配套链接重定向、失败兜底与格式修复。**wiki 不反向改写记忆**（纯派生）。

**关键实测**：223 会话 / 1562 条记忆 → 第一级 **660 页** → 第二级 **20 域 / 233 页**
（压缩比 2.8:1）；链接死链 92.6% → **0%**。

**顺带发现的通用问题**：提示词里的"内容 ≤120 字"是软约束，**没有任何模型稳定遵守**
（超标率 24%~53%）→ 改为代码级硬截断；模型"返回了内容但 JSON 坏了"原先只能整条丢弃
→ 增加格式修复模型救回被截断的内容。

## ② 可运维的知识库（09-19）

**解决什么**：一次性脚本变不成系统。这一天补的是"长期运行需要的那些东西"：

- **它会知道自己过时了**：编译清单（输入指纹）+ 对齐审计（引用/覆盖/死链）
- **它能增量更新**：脏会话重编 + 脏域局部重编 + 链接修复 + 清单刷新；由**写入时
  触发器**驱动（时点档 / 脏记忆攒够 / 每日首写），不需要常驻调度器
- **它可回滚**：索引库整库 + wiki 产物目录**原子快照**（LLM 产物重编会漂移，
  反馈演化值更是无法重建）
- **它可运维**：失败清单跨次累积 + 定向补跑（CLI / HTTP / Python 同一份实现）
- **它接上了写入链路**：`memory_save` 直写的记忆此前对 wiki **完全不可见**，
  补齐落表 + 历史回填

**同时段的事故与加固**（详见架构文档 §12）：测试污染导致 79 个 L1 产物丢失（此后
测试禁止解析真实 wiki 目录）；L2 混版（此后全量重跑统一版本 + 自动快照）。

## ③ 知识与记忆合流 + 召回质量（09-20）

**解决什么**：把"知识库"和"记忆"合成**一个检索面**——知识页不再只是产出物，而是
与消息、记忆同池竞争的第三层（`kind=page`）。此后召回质量成为主要战场。

**关键实测结论**（都是靠真实查询证伪出来的）：

- **页面融合分与相关性甚至反相关**（相关页 0.21×top vs 噪声页 0.63×top）——
  分数门限必然误杀；结论是**分区间判别**：高分看分数、低分看字面证据
- **"证据"同样不能当门槛**：拼错查询下，语义最相关的页面只有最弱的池内信号，
  而噪声靠全局向量分进来——按证据筛会**同时做错两件事**
- **"没料"时宁可少给**：无关查询从"8 条全是页面"降到 0~2 条；拼错查询靠
  "低分字面兜底席"救回真相关页
- **专名盲区**：`command code` 这类**多词英文专名**此前没有任何通道覆盖——
  12 个相关单元有 11 个连候选池都进不去 → 新增**短语精确匹配通道**

**当前能力**：六路通道融合（向量 / 全文 / 标识符 / 短语 + 页面专属两路）、
页面准入策略、**召回严格度档位**（1~5，默认 3）、结果带层级与来源标注
（`kind` × `origin`）、快照保留份数可配。

## 即将做（Roadmap）

按优先级（**当前主推 1～3**）：

| # | 事项 | 为什么重要 | 状态 |
|---|---|---|---|
| 1 | **外部文档投喂通道** | 目前知识只来自"与 Agent 的对话"；投喂 PDF/网页/笔记才能把外部资料变成一等公民（素材层存**原件快照 + 转换后正文**两份 → 编译成文档页 → 参与融合 → 标 `origin: external`） | 架构已定，未实现 |
| 2 | **召回精排（rerank）** | 当前噪声与排序的天花板：**分数与证据都无法区分"高分噪声"与"低分相关"**（拼错查询里噪声 0.805 排在真相关 0.204 前面）。两条路：本地 cross-encoder（无 API 费用、~100-300ms）或 LLM 条件精判（复用现成 `LLMFinalJudge`） | 方案已评估，未实现 |
| 3 | **高频单词召回盲区** | 搜 `command` 召不回 Command Code 记忆（高频词 + FTS 名次分对长文本不利 + 标识符通道要求 ≥12 字符）。候选：FTS 计分改归一化 bm25 / 罕见词也走字面通道 / 层级偏置（同分时记忆优先于原始对话） | 已诊断，未定方案 |
| 4 | **面板 UI 统一重做** | 面板已与后端能力脱节（六路召回、层级/来源、档位都没有对应 UI）。**用户明确要求放最后做** | 待后端定稿 |
| 5 | **`log.md` + Obsidian 验证** | Karpathy 三件套的最后一件（图谱/反链/frontmatter 已具备，缺时间线日志）；Obsidian 打开验证是零代码 | 未开始 |
| 6 | **通用修复回移 main** | `branch-divergence.md` 列的 5 项与 wiki 无关、`main` 缺失；建议新建 `feat/llm-robustness` | 已记录，待决策 |
| 7 | 收尾小项 | 合并记忆溯源多一跳（`merged_from_json`）；`wiki --action runs`（编译历史查询）；3 个未被 L2 覆盖的 L1 孤页；隔离目录 `out_l2_quarantine_99/` 去留 | 待办 |

Gemini CLI / CodeBuddy）、记忆折叠压缩（超长会话压缩、相邻轮折叠）、存储扩展
