# feed — 外部投喂转译层

> 设计文档：[`../feed-adapter-plan.md`](../feed-adapter-plan.md)（v2.2，**为什么这么设计**）
> 本文是**模块文档**：职责边界 / 数据形态 / 怎么用 / 怎么排查（**改代码前先读它**）
> 状态：**M0 地基 + M1（素材库 + T1 文本直通）已实施**；M2 入图并列、M3 网页公众号、M4 PDF/图片未做

---

## 1. 职责边界（别和 `adapters/` 混）

| | `agentmemhub/adapters/` | `agentmemhub/feed/`（本文） |
|---|---|---|
| 干什么 | **采集**内部 Agent 会话 | **转译**外部素材 |
| 输入 | DSH / Qwen / ZCode… 的会话存档 | 本地文件 / URL / PDF / 图片 |
| 输出 | `conversations` + `events`（源库） | 统一 md（**交付物**）+ 登记表 |
| 下游 | 摄取 → 蒸馏 → wiki 编译 | **知识库页面层**（与 wiki **并列**，不进编译链） |

两者形态同构（注册表 + 认领 + 统一产物），但数据流方向与服务对象完全不同，**不合并**。

**并列的含义**（用户 2026-10-10 拍板）：投喂内容**不进**记忆/蒸馏/wiki 编译 ——
它只以"知识库页面"的形态存在，召回时与自有 wiki 页面同台竞争（`origin` 维度可区分）。

## 2. 三段物料（用户明确要求的三份保留）

```
第 1 段  raw/      不可变原件字节，**内容寻址** raw/<sha256 前 2 位>/<sha256>.<ext>
第 2 段  mirror/   转译中间形态，按 doc_id 归档（HTML 源码 / 渲染快照 / OCR 中间态）
第 3 段  kb/       最终 md（**统一交付物 / 知识库本体**）—— 默认 exports/wiki_work/out_feed/
```

三个位置由 `feed` 配置段给出（`db` / `store_dir` / `kb_dir`），
经 `Config.feed_paths()` **统一解析成绝对路径**（三处必须同源，否则会写出
"原件进 A、登记表指向 B"这类错位）。

**为什么原件走内容寻址的文件系统而不是塞进库 BLOB**：溯源强度由 hash 锚保证，不必把字节放进库里
——而库一旦进快照，每份快照都要复制一遍素材（×`snapshot.keep` 放大）。内容寻址顺带带来两个好处：
**同内容重复投喂天然去重**，且文件可被任何工具直接打开。

**`materials.db` 是独立库且不进快照轮换**：它只是"元数据 + 指针"，丢了能从 `raw/` 重建
（原件才是不可再生的那一份）。

## 3. 数据结构
### 3.1 `FeedDocument`（转译层**对内唯一契约**）

所有转换器的输出都收敛成它（`feed/base.py`）：

| 字段 | 说明 |
|---|---|
| `doc_id` | 内容锚 = `sha256(原件字节)[:16]` —— **同字节 ⇒ 同 doc_id**（幂等的根） |
| `title` / `markdown` | 标题 / **最终 md**（统一交付物） |
| `kind` | `text` \| `url` \| `wechat` \| `pdf` \| `image` |
| `source_ref` | 原始路径或 URL（人可读的"从哪来"） |
| `doc_time` | **文档自身时间**（发布/修改），**不是投喂时刻** —— 时间衰减按它算 |
| `mirror` / `converter` | 镜像文件表 / `名字@版本`（**重转判据**） |
| `quality` / `warnings` | 质量自评：既是给人看的指标，也是"要不要升级到 LLM 兜底"的**触发器** |

**空正文直接 `FeedError(kind="empty")`** —— 空页面会变成"标题正当、内容为空"的召回单元。

### 3.2 `materials` 表（登记表 + 状态机）

```
received ──convert──▶ converted ──publish──▶ published
    └────────────── failed ◀──────────────┘（retracted：撤下交付物但原件保留）
```

`failed` **不删原件** —— 换转换器版本后可以 `feed retry`（这就是三段保留的价值）。

## 4. T2：网页与公众号（M3 已落地）

**实测驱动的三条**（2026-10-12，用真实链接）：

| 结论 | 证据 |
|---|---|
| **UA 是硬需求** | 同一公众号链接：不带浏览器 UA 只拿到 **18 KB 桩页**，带 UA 拿到 **3.6 MB 真页** |
| **trafilatura 够用，不必自写抽取器** | 公众号抽出 3,492 字 + 正确标题 + 发布日 `2024-09-26`；文档站 84,737 字 |
| **信噪比 0.1%** | 3.6 MB 真页里可见文本只有 4,320 字 ⇒ 把原件喂模型 ≈ 90 万 token 换 4 KB |

> **修正一个预判**：计划原以为"公众号必须特化解析"。实测反过来 —— 它的 DOM 极其规整、
> trafilatura 直接就能抽；**难点在"访问"（反爬/UA），不在"解析"**。所以 `wechat.py`
> 只做两件事：**定向兜底**（通用抽取太短时切 `#js_content`）与**发布时间解析**。

**三级取回**：① 脚本直抓（httpx，走代理）→ ② Playwright 渲染（`feed.fetch.renderer`，
**M3.1 未接**）→ ③ **人工兜底**：`feed add --stdin`（粘正文）或浏览器另存 HTML 后 `feed add`。
检测到反爬/异常页**不硬闯**，报错直接给兜底指引（反爬是军备竞赛，兜底是一等公民）。

**图片**：trafilatura 的 markdown **实测会丢图**（真页 14 张 `<img>` → 0 张），
所以本地化做在 **HTML 层面**：下载进 `mirror/<doc_id>/images/` 并改写 `src`；
`mirror/index.html` 存**抓到的原始源码**，改写版另存 `localized.html`；
抽取器丢图时**如实记警告**（不静默失真）。

**两个易错点**（都有测试）：
· **URL 的身份是"最终 URL"，不是内容 hash** —— 动态页面字节每次都变（时间戳/CSRF），
  按内容判会"每投喂一次多一条"；
· **`var ct` 不是发布时间**（更接近渲染时刻），真页也没有 `#publish_time` 元素
  （只出现在 URL 编码的 JSON 里）⇒ 以 trafilatura 元数据日期为准。

## 5. T3 · PDF（M4 已落地）

**"PDF 不是一种东西"** ⇒ `pdf.py` 的职责是**先探再派**（`probe → route`），不是一个解析器：

| 亚型 | 客观判据 | 处置 | 产出 |
|---|---|---|---|
| **T3a** 文字版·单栏 | 每页 ≥ 50 字符、无线条表格 | `pypdf` 抽文本层 | 近乎无损（`quality=1.0`） |
| **T3b** 文字版·含表格 | `find_tables()` 命中 | `pypdf` + `pdfplumber` 重建表格 | `quality=0.85`（表格有重构损耗） |
| **T3c** 扫描件 | 平均每页 < 50 字符 | 逐页渲染进 `mirror/<doc_id>/pages/` | **报 `needs_ocr`**（本档不产正文） |
| **T3d** 加密 | `is_encrypted` 且空密码打不开 | 直接报 `encrypted` | 要密码，**不硬闯、不猜** |

判据全部**客观可算**（不看文件名、不猜来源）—— 真实素材上"猜来源"必然出错，
而错判的后果是**静默失真**：把扫描件抽成空正文、把表格抽成散乱文字，
两者都"看起来成功了"。

**⚠️ 一处硬顺序约束（被加密夹具实测逼出来）**：加密档**不能先碰 `len(reader.pages)`**——
未解密就访问会抛 `FileNotDecryptedError`，加密档会变成 `crash` 而不是可处置的 T3d。
所以流程必须是"先判加密 → 再谈页数"
（`tests/test_feed_pdf.py::test_探针_加密档_判_T3d_且探针本身不抛异常` 守它）。

**表格区域剔除是"危险操作"，配了两道闸**：`pdfplumber.extract_text()` 里**包含**表格文字，
不剔除的话同一批字会以"流式正文 + 表格"两种形态各出现一次；但剔除是从正文里**删东西**，
所以：

| 闸 | 内容 | 拦住的真实事故 |
|---|---|---|
| ① **表格要有意义** | ≥2 行且 ≥2 列 | 一行等宽字体代码被误检成"1 行 2 列"，照单全收会把那行**从正文删掉**，而它又不足以构成表格 ⇒ **内容两头落空、永久丢失** |
| ② **剔完要不丢字** | `剔除后正文 + 表格内容` 必须覆盖原页全部字符（多重集比较，容忍 2 字） | 表格 bbox 里的字有一部分没进 `extract()` ⇒ 被剔掉却无处可去 |

闸②不过就**放弃剔除**（保留完整正文、接受表格文字重复）并如实记 warning ——
**重复很难看，丢字是数据事故**，两者代价不对称。
另：`tables_skipped` 会记进 `meta`（"看见了但没当表格"必须可查），但**不记 warning**
（没有造成失真，不该把整篇标成低质量）。

⚠️ 校验必须**同源**：拿 pypdf 的文本跟 pdfplumber 的过滤结果比，光空格处理差异就会被判成
"丢字"，于是永远不敢剔除（闸②形同虚设）。所以 T3b 路由下整篇正文统一改用 pdfplumber。

**能力边界（明说，不假装）**：
· **公式拿不回来** —— PDF 里的公式是排版符号而非语义，任何解析器都一样（C 维度结构性上限）；
· **页内图片位置不保留** —— 文本层不含图片坐标，抽出的内嵌图只落 `mirror/`；
· **T3c 未接 OCR** —— 只做到"探测 + 渲染 + 指路"，OCR 属 T4。

**真实素材验收**（两份，都是用户提供的真实文档）：

```
① Intel_Proprietary_License.pdf   86,805 B  → T3a · 2 页 · 10,333 字 · 质量 1.00
② 文字文稿1.pdf                    325,136 B → T3a · 2 页 · 1,582 字 · 质量 1.00
```

真机共抓到 5 处**夹具永远不会暴露**的缺陷（前两条来自 ①，后三条来自 ②）：
① 元数据 `/Title` **被写坏了**（停在 `…[v2022.12`，正文首行才是完整的 `…[v2022.12.20]`）
⇒ 加了"首行更完整则采用首行"的相似度判据（**不能用"谁更长"**：截断的元数据标题
因为多了 `C2A … (Commercial Use)` 反而更长）；
② `/CreationDate` 末尾的 `Z` 被旧实现丢掉、又按本地时间解释 ⇒ `doc_time` **偏 8 小时**
（时间不是装饰，召回侧的时间衰减按它算）；
③ **误检表格吞掉正文**（最严重，见上表闸①）：`page.get_by_role("button", name="Submit")`
一整行从知识库里消失了，而它本该是这份文档里最有技术含量的一句；
④ **首行被行宽硬切**：`…今年有六年有余的工作经` + 第二行的 `验。`
—— 直接拿首行当标题就是一句断掉的话（现在会缝合，中文不补空格、英文补）；
⑤ **标题取成了 WPS 默认文件名「文字文稿1」**（那份 docx 完全没用标题样式）。

**依赖与许可（计划 §10.2 的 R2 就此结案）**：`pypdf`(BSD-3) 进主依赖；
`pdfplumber`(MIT) + `pypdfium2`(**BSD-3/Apache-2.0**) 进可选档 `feed-pdf`。
**渲染没有用 PyMuPDF**（AGPL-3.0，有传染性）—— `pypdfium2` 是许可完全宽松的替代品，
也不用像 `pdftoppm` 那样在 Windows 上额外分发可执行程序。
缺可选档时**不静默降级**：T3b 退化为 T3a 并记 warning、T3c 报 `needs_renderer`
并给出 `uv sync --extra feed-pdf` 指引。

## 6. DOCX（M4 已落地）

**`.docx` 不属于"PDF 那一类"**（计划 §7.0.1 专门纠正过这个误判）：它本质是 ZIP + XML，
标题/大纲级别/表格/图片**本来就在文件里**；`python-docx` 是确定性抽取 ——
零 LLM、零猜测、可复现，与 T1 同级。把它按 PDF 估工期是这份计划早期最贵的误判。

**最大的坑：段落与表格在 XML 里是兄弟节点且交错。** `document.paragraphs` 与
`document.tables` 是**两个独立列表**，分别遍历会让表格全部挤到文末、文档顺序全丢。
必须按 `w:body` 的子节点顺序走（`iter_block_items`）。夹具 `sample.docx` 里
"表格前后的段落"就是这个坑的哨兵 —— 顺序错了那条断言立刻红。

| 风险 | 处置 |
|---|---|
| **样式名不确定**（中文版 Word 是 `标题 1`，自定义样式名千奇百怪） | 判据落在 **`w:outlineLvl`**（大纲级别才是标题的本质属性）+ 中英样式名兜底 |
| **完全没用标题样式**（标题落到文件名上，而那是 WPS 的默认名「文字文稿1」） | 标题多一档**正文首段**兜底 + 默认文件名判为 junk —— 见下 |
| 超链接里的文字 | 不用 `paragraph.text`（**漏掉 `<w:hyperlink>` 里的 run**），按 XML 取全部 `w:t` |
| 合并单元格 | markdown 管道表表达不了 ⇒ **如实打标**并把质量降到 0.85（不静默） |
| 图片 | docx 有**真实位置**（`w:drawing` 就在某个段落里）⇒ 插回原位，比 PDF 那一档强 |
| `.doc`（97-2003） | **根本不是 ZIP**，`python-docx` 读不了 ⇒ 显式拦住并给"另存为 `.docx`"指引（不报"文件损坏"这种误导性错误） |

**标题兜底的档位**（判据单点在 `feed/titles.py`，PDF/DOCX 共用）：
`core title` → 首个一级标题 → **正文首段** → 文件名 → 占位标题。

为什么必须有"正文首段"这一档（真实素材逼出来的）：一份求职 docx **完全没用标题样式**
（38 段全是正文）、core title 也为空 ⇒ 标题落到了文件名上，而那是 WPS 的默认名
「文字文稿1」—— **默认文件名比正文首段更没有信息量**（前者对所有这类文档都一样）。
首段要**限长**（60 字），限长或占位时都会记 warning：一个像是原文、其实是半句话的标题，
比一个明显是占位的标题更危险。

**两个假告警/真告警的教训（都在真实素材上暴露）**：
· **假告警比漏报更伤**：合并检测最初用 `id(cell._tc)` 比对象身份，而 lxml 的元素代理
  **不保证身份唯一** ⇒ 普通 3×3 表格被误判"有合并"、质量分 1.0→0.8；改判
  `w:gridSpan > 1` / `w:vMerge` 存在；
· **文案不能自相矛盾**：`low_quality` 的语义是"质量分低 **或** 有告警"，而控制台一度打成
  「质量偏低（1.00）」—— 两者必须分开说。

**真实素材验收**（两份）：

```
① Word 12.0 原生另存的 docx   43,115 B  → 标题层级/顺序/表格/列表/图片全对 · 1.00
② 文字文稿1.docx              153,014 B → 1,657 字 · 质量 1.00 · 标题=正文首段
```

② 是本机没有真实 docx 时，用 **Word 原生另存**（COM 打开夹具 → `SaveAs`）造出的
"真实 Word 签名"样本；后续用户给的真实 docx 又把"默认文件名当标题"这条补上了。

## 7. 怎么用（CLI）

```powershell
agentmemhub feed add <文件路径> [更多路径…]     # 投喂（默认动作，可省略）
agentmemhub feed add --dry-run <路径>           # 只查重与认领，不写盘
agentmemhub feed add --force <路径>             # 同内容已投喂过也重跑（修标题/换转换器后用）
agentmemhub feed list [--status failed] [--low-quality] [--json]
agentmemhub feed show <doc_id>
agentmemhub feed retry <doc_id>                 # 重转：优先原始来源；来源不可达时**自动回落 raw/ 原件**
agentmemhub feed retry --from-raw <doc_id>      # 强制用 raw/ 原件重转（不碰原始来源）
agentmemhub feed retract <doc_id>               # **撤下**（可恢复）：删交付物+收敛投影，**原件保留**
agentmemhub feed forget <doc_id> [--purge]      # **清除登记**；--purge 才连原件一起删
agentmemhub feed lint [--json]                  # **确定性体检**；P0>0 时退出码 1
```

**撤下与清除的分界**：`retract` 撤下投喂内容但**原件保留** ⇒ `reconvert` 能把同一份
重新发布出来（不是单向门）；`forget` 连登记一起清除，**原件默认保留**，只有显式
`--purge` 才删。理由是同一条：`raw/` 是不可再生的那一份，其他两层都能从它重建。

**为什么不需要回收站**：交付物（kb）是**派生物**，删了随时能从原件重建 —— 这正是
三段保留的回报。而回收站恰恰会引出"扫描器漏排回收站 ⇒ 真断链被掩盖"的**双向失效**
坑（参考实现 `lint.py` 踩过，见计划 §11.4）。所以这里**直接删，不设 `.trash`**。

**投喂后要让交付物进召回面**（M2 起）：

```powershell
agentmemhub wiki --action index-pages    # 投影**所有页面根**（L2 自有 + 投喂交付物）→ units
```

`wiki --action update` / 面板增量更新也会顺带投影一次（都走
`wiki_index.project_pages`，根集合由 `page_roots()` 单点给出）。

**为什么 `retry` 要有"回落 raw"这条**：三段保留的全部意义就是"原件不可再生、其余都可重建"。
若重转只能靠 `source_ref`（用户的下载目录），用户一清理文件就再也转不了 ——
**保留下来的原件等于白存**（2026-10-12 核对投喂数据时发现该缺口）。
回落后 `source_ref` **不被改写**（仍指向原始路径），溯源不受影响。

动作既支持自然写法 `feed add X`，也支持项目惯例 `feed --action add X`；
**flag 可以夹在中间**（`feed add --force X`）—— 这一条是对 feed 特意放宽的
（argparse 默认会把 X 判成"unrecognized arguments"，见 `cli.main()` 里的说明）。

`MCP` 工具（`feed_add` / `feed_list`）与面板入口**归 M5**。

## 8. 并列关系与多根投影（M2）

投喂交付物与自有 wiki **并列**（用户 2026-10-10 拍板），落在**两个独立的页面根**里：

```
页面根（由 wiki_index.page_roots() 单点定义）
├── exports/wiki_work/out_l2_mimo/   ← 自有记忆长出来的（**主根**）
└── exports/wiki_work/out_feed/      ← 外部投喂的交付物（**非主根**）
```

两者都投影进 `units(source='wiki')`，靠 `origin`（`native`/`external`）区分，
一起参与召回融合（默认混排）。

**多根投影的三个安全设计**（改动 `project_pages` 前必读）：

| # | 设计 | 不这么做会怎样 |
|---|---|---|
| ① | **主根不加根标签**，其余根用目录名 | 给所有根加标签 ⇒ 主根既有 `src_id` 全变 ⇒ **库里几百个页面 unit 整体重键**，挂在它们上的价值分与 👍👎 反馈变孤儿 |
| ② | **标签按配置位置定**，不按"已存在的根" | 某个根临时缺席时另一根标签漂移 ⇒ 身份变 ⇒ 旧行被判"磁盘上已不存在"而清掉 |
| ③ | **清扫只清本轮真扫过的根** | 某个根暂时不可用（目录被移走/还没建）⇒ 它的投影**被全部删光**，等它回来再重建 |

**`wiki_path` 是绝对路径**（不是根内相对路径）：它是"两阶段召回第二阶段"的入口，
消费者（MCP 输出的 `wikiPath`）要能**直接打开**。老数据是相对路径，下一轮投影自动重写。

**为什么 `out_feed` 不放进 `out_l2_mimo`**：`wiki_aggregate` 的写盘是**整域替换**
（会 `rmtree` 掉"不属于本轮"的域目录），放进去迟早被删。两个根**互不嵌套**是结构性保证
（有测试锁）。

## 9. 日志与排查

事实流：`logs/feed.log`（JSONL，标准头五项在写入口统一补齐）。

| event | 何时 | 关键字段 |
|---|---|---|
| `feed_received` | 原件已落 raw | `doc_id` `raw_path` `bytes` `sha256` |
| `feed_converted` | 转译完成 | `converter` `title` `chars` `quality` `warnings` |
| `feed_published` | 交付物已写 kb | `kb_path` `quality` `low_quality` |
| `feed_failed` | 任一步失败（`level=error`） | `error` `error_kind` `retryable` |
| `feed_skipped` | 幂等命中，**不是失败** | `reason="duplicate"` |

**排查剧本**：

```powershell
# 这次投喂跑到哪一步就断了？
rg '"doc_id": "<doc_id>"' logs/feed.log
# 哪些失败是可以重试的？
rg '"event": "feed_failed"' logs/feed.log | rg '"retryable": true'
# 素材库里现在什么状态（落库侧，与事实流互补）
agentmemhub feed list --status failed
```

⚠️ **`error_kind` 决定处置方式**，不要只看错误文本：

| kind | 处置 |
|---|---|
| `unsupported` | 要人换格式（`.doc` 老格式、未知类型），重试无用 |
| `not_found` | 文件不在，要人给路径 |
| `encrypted` | PDF 加密，要密码（**不猜、不爆破**），重试无用 |
| `needs_ocr` | 扫描件：**原件与页面镜像已保住**，接上 T4 通路后 `feed retry` 可续跑 |
| `needs_renderer` | 扫描件 + 渲染器没装 ⇒ `uv sync --extra feed-pdf` |
| `convert` | 转换器内部失败，**可重试** |
| `needs_llm` | 开关没开（`feed.convert.llm`） |
| `empty` | 转出空正文，不可重试（空正文绝不进知识库） |
| `registry` / `crash` | **代码 bug**，要修而不是重试 |

体检里 `needs_ocr` / `needs_renderer` 会以 **P1 `awaiting_ocr`** 露头（不是 P0）——
能力缺口不是数据不一致，但也不该静默躺在库里；其他 `failed` 素材报 P1 `failed_material`。

### 确定性体检（`feed lint`）

灵感来自参考实现的 `lint.py`（它唯一的实质代码，352 行、零 LLM）：
**LLM 负责产出，脚本负责校验**。本项目此前只有 `obsidian.verify()`（依赖外部程序、
索引会过期），正因缺这一层，"顶层 index 链接指向 `.json`"那个 bug 才能活很久。

投喂链路尤其需要它：**四份东西必须严丝合缝** ——
登记表（`materials.db`）↔ 原件（`raw/`）↔ 交付物（`kb/`）↔ 投影（`units`）。
任何一处错位都是**静默的**：不报错、不让测试变红，只是"搜不到"或"点开是空的"。

| 级别 | 检查 |
|---|---|
| **P0** | 原件丢失 · 交付物丢失 · 交付物未登记 · frontmatter 缺字段 · `doc` 与登记不符 · `origin` 不是 external · **投影残留**（撤下没清干净 ⇒"删了还能搜到"）· 投影指向不存在的文件 · 投影 origin 错 · **页面根互相嵌套** |
| **P1** | 低质量（**打标但不拦发布**，§7.5）· 索引库/配置不可用（跳过而非失败） |

`P0 > 0` 时**退出码 1**，可直接当提交门槛或巡检脚本。

> **测试安全**：`run_lint` 的 `index_db` 可注入 —— 不注入就会读**真实索引库**，
> 结果依赖真实状态、测试不确定。撤下用的 `_reproject()` 则带**沙箱熔断**
> （它写的是真实索引库）：测试里会返回 `{"skipped": "test_sandbox"}`。

## 11. 不变量

1. **未知类型必须显式报错**，绝不静默跳过（本项目踩过"未知 source 静默跳过"的坑）。
2. **原始件永不丢**：认领失败、转译失败都要先落 `raw/` —— 否则将来补上转换器也无法重转。
   **推论：重转不得依赖原始来源可达** —— `retry` 在来源消失时必须回落到 `raw/` 原件
   （`reconvert()`），否则"原件保留"只是摆设。
3. **`kb` 文件路径只由 `doc_id` 派生**（`<doc_id>.md`）—— 投影的 `src_id`/`seq` 由路径派生，
   路径必须稳定；可变的标题放 frontmatter。
4. **`doc_time` 是文档自身时间**，不是投喂时刻（与 `distill._origin_time` 同语义）。
5. **`FeedDocument` 是唯一契约**：下游只认它，不为某种格式开后门。
6. **转译层的对外副作用必须可审计**：每个事件进 `logs/feed.log`，`depth` 要算对
   （隔了包装层必须 +1，否则行号恒等、字段作废）。
7. **质量自评低于阈值仍然发布，但必须打标**（`feed list --low-quality` 可筛）——
   静默失真比"拒收"更危险（`docs/feed-adapter-plan.md` §7.5）。
8. **页面根只由 `page_roots()` 定义**（`wiki_index.py`）—— CLI / wiki 管道 / 面板
   各写一份必然漂移；两个根**互不嵌套**（否则一方的整域替换会毁掉另一方）。
9. **多根投影的三条身份纪律**（见 §8）：主根不加标签、标签按配置位置定、
   清扫只清本轮真扫过的根。违反任一条的后果都是**数据损失**（重键 / 投影错乱 / 误删）。
10. **`wiki_path` 是绝对路径** —— 它是两阶段召回第二阶段的入口，必须是"能直接打开"的
    形态，否则消费者拿到也读不了。
11. **派生物不需要回收站**：交付物（kb）与投影都能从原件重建，所以撤下**直接删**；
    只有 `raw/` 是不可再生的那一份 —— `forget` 默认保留它，`--purge` 才删。
12. **碰真实路径的出口必须有沙箱熔断**：`_reproject()` 写的是真实索引库，
    测试沙箱下必须跳过（本项目 2026-09-26 的事故就是"测试经真实路径改了真实产物"）。
13. **格式分派必须"先探再派"，且判据客观可算**：不许看文件名/来源猜类型。
    ⚠️ 探针的**读取顺序**也是不变量的一部分：加密必须先于页数（否则加密档表现为崩溃
    而不是可处置的 T3d）。**判据可单独测**（`probe()`/`route()` 是纯函数）——
    端到端测试只能反推判据，测不出"判错了哪一条"。
14. **不可再生的中间产物要在报错之前先落地**：T3c 是"**先渲染进 `mirror/`，再**抛
    `needs_ocr`" —— 素材进来一趟，原件与可见内容都该留下；反过来的话，
    OCR 通路接上后又要重新抓一次原件。
15. **能力缺口与数据损坏必须分开报**：`needs_ocr`/`needs_renderer` 是**能力没接**
    （原件都在），所以体检里是 P1；数据不一致（原件丢了、交付物没了、溯源断了）才是 P0。
    混在一起会让"体检红了"失去指向性。
16. **任何"从正文里删东西"的操作都必须先证明不丢字**。表格区域剔除是最典型的例子：
    它是从正文里**删**字符，所以必须先做覆盖校验（`剔除后 + 表格内容 ⊇ 原页字符`），
    并且**校验两端必须同源**（拿两个引擎的输出比，光空格差异就会让校验永远不敢放行）。
    校验不过就**放弃剔除**（宁可重复），因为"重复很难看、丢字是数据事故"。
    ⚠️ 2026-10-15 真实素材事故：一行代码被误检成"1 行 2 列"表格，照单全收 ⇒
    那行字**从知识库里永久消失**（连"语"字都被吞了）。
17. **标题是"替代品"时必须让人看见**。标题四个来源都可能不可用（元数据被写坏、
    文档没用样式、首段过长、文件名是「文字文稿1」）；用替代来源时**限长 + 记 warning**，
    绝不悄悄给一个像是原文的标题 —— 那会被当成文档真标题一路用下去。
    判据单点在 `feed/titles.py`（PDF/DOCX 共用），改判据要同时想两边的后果。
